# 26.2 エンティティアイコンの生成

2026-10-28 JST。対象は26.2のみ。関連要件F48／F16、初回の検討記録は entity-icons-design.md。

## 表示の優先順位

- 既存の専用顔画像は優先して使用する。長方形の画像は縦横比を維持して中央へ収める。ミニマップ・全画面・アイコン選択の2D描画で共通。
- タラ・サケ・フグ・熱帯魚と、専用画像がない種類は、クライアントに登録された実エンティティのrendererから画像を生成する。MOD追加エンティティも同じ経路を使う。
- 生物のモデルから安全に頭を取り出せる場合は頭とその子パーツを描く。取り出せない場合、頭の描画に失敗した場合、頭の画像が透明だった場合は、全身画像へ切り替える。
- 生成待ち・失敗中の魚には、魚種別のitem画像を表示する。それもない場合や未知の種類には、既存の色付き記号を表示する。

画像の保存・取得のためにserver MODを必須にしない。既存のエンティティ表示設定、64ブロックの3D収集範囲、高低差フェード、プレイヤー／waypointの優先順は維持する。

## 頭だけを生成できる条件

`LivingEntityRenderer` が実際に送信したbase model・state・render type・tintを調べる。
`HeadedModel.getHead()` またはroot直下の `head` を手掛かりに、親の変換を推測せず描けるパーツだけを採用する。
モデルが独自の階層・別の骨格ライブラリを使う場合、あるいはsubmit中に別のmodelへ切り替わる場合は、全身へ戻す。

頭の画像にはそのパーツの子（鼻・耳等）を含む。一方、別render layerの装備・毛・職業等はbase headだけでは再現できない。
全身経路は登録rendererのlayerも利用するが、独自shader・ワールド依存の特殊rendererまで完全互換を保証するものではない。
head probeと描画では、共有modelの位置・回転・scale・visible・skipDrawとrendererのmodel参照を保存・復元する。実ワールドのentityを回転・変形させない。

## キャッシュと負荷

生成元は現在ロードされている実個体。描画時のUUID検索を繰り返さず、tickごとにプレイヤーから64ブロック以内の近い順、最大1024体をindexへ保持する。
画像はclient内の一時textureとして最大128件をLRUで保持する。通常表示はそのtextureを参照するだけで、毎フレーム3Dモデルを描き直さない。
生成開始は100ms間隔、同時処理は2件まで。失敗したkeyは5秒待って再試行する。

画像生成は64×64の透明な一時描画先を使用し、生成時だけ非同期GPU読出しを行う。
alphaを検査して空画像を拒否し、余白を取り除き、上下とpremultiplied alphaを補正して通常textureへ登録する。
全身と横向きの魚の収まりはモデルの投影範囲を優先し、取得できなければ当たり判定の範囲を使う。

vanillaの魚は色柄・種類・膨張等の見た目をkeyへ含め、同じ外見の画像を共有する。
MODの魚subclassをこのvanilla専用keyで混同せず、未知のMOD個体は完全なtype IDとUUID・成長状態で区別する。
未知の外見を全NBTやanimation tickで無制限にkey化しない。
未知個体の画像は約10秒経過した後、古い画像を表示したまま更新する。未生成個体の要求がある間は、その初回生成を優先する。
更新失敗で既存画像を消さず、全個体のkeyを定期的に一斉変更して生成待ちをやり直すこともない。

切断・world切替・resource reloadでは世代を更新し、古い非同期結果をuploadしない。
GUIの抽出済み描画が参照し得るtextureは、その場で破棄せず2 client tick後に解放する。
データの永続保存や新しいnetwork channelは追加しない。再接続・reload後は必要な画像を再生成する。

## 制約と検証

任意のモデルから「頭らしい形」を画像認識で探す方式ではない。公開モデル構造から安全に特定できた頭だけが対象となる。
頭のないモデル、深く入れ子になった骨格、未知の描画方式は全身画像または色付き記号になる。
巨大モデルの追加effectや独自geometry、読み取り不能なrenderer、未ロード個体には表示上の制約が残る。
Web画像配信・任意のprovider API・専用アイコン定義UI・他Minecraft版への移植は今回の対象外。

headless testsは実装のキャッシュ・世代分離・画像変換・比率・framing・モデル状態復元を検査する。
実GPU／実画面／実MOD組合せの見た目・FPSをfixtureだけで確認済みとは扱わない。
最終のcheck・native build・配置の結果と限界は [fork-change-register.md](fork-change-register.md) の本作業記録を参照する。
